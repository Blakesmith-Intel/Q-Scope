**Scope:** retain the 20 November approved map/wallboard, seven genuine rain scans spanning 30 minutes, independent Doppler, official-only wind, flood logic, warning reissues, cyclone, outages, roads, QFD, region filters and export. Rainfall rollover invalidates the prior reporting day at 09:00 AEST (23:00 UTC), aligns rainfall cache expiry, and checks positive first-hour since-9am totals against the same station/region/source edition's last-hour total. Unsupported readings are excluded, not reported as zero, and known pending readings are retained in the current browser session until evidence of recovery. No individual gauge observation timestamp is exposed by the existing parser; this is a consistency screen, not proof of a station reset. AEP thresholds, five-minute polling and all other retrieval paths remain unchanged. Station 529090 regression uses synthetic values, not a recovered live record.

The existing IDQ60920 statewide source remains authoritative: the parser exports nullable `todayMaximumGustUtc` from the `maximum_gust_kmh` element's own `time-utc` attribute, or its timezone-qualified `time-local` fallback, normalized to UTC. It does not substitute the station period's `observedUtc` or recompute a peak from history. The wind gust report appends the peak timestamp in AEST to each published daily maximum; the wallboard shows the peak time alongside the highest-gust station. Missing/unparseable peak time is explicitly unavailable; gust speed remains available independently. The reporting period, station sorting, severity, ten-minute frontend refresh, upstream request/cache policy and other products are unchanged. The wind regression suite covers differing peak/latest times, missing and invalid timestamps, local-offset fallback and both view bindings. The existing relay deployment path now includes changes to the shared wind parser; the Pages overlay and dashboard asset cache versions were advanced for this fix.
